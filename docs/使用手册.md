# 使用手册

这份文档讲三件事：**它能做什么、怎么装怎么用、出了问题怎么查**。

---

## 一、它能做什么

四类能力，按"你在编辑器里看到的形态"分：

| 形态 | 触发方式 | 适用场景 |
|---|---|---|
| 灰色小字 | 光标停在某行 0.3 秒 | 当前行有**可原地修好**的错误 |
| 灯泡 | `Ctrl+.` | 修复要跨行（改声明、插 `#include`、补 `}`） |
| 波浪线 + Problems | 自动 | 能指出问题但修法不确定 |
| 补全模板 | 输入函数名前缀 | `pr` → `printf("%d\n", )` |

### 1. 灰色小字 + `Tab`

光标所在行有能就地修好的问题时，停手 0.3 秒后出现灰色建议。**只需要看光标那一行**，不会打扰你别处。

```c
scanf("%d", x);        ← 原始代码
scanf("%d", &x);       ← 灰色 & 出现在 x 前面，按 Tab 后变成这样
```

同一行有多处问题时合并成一次修改，按一次 `Tab` 全部应用。

按 `Esc` 表示"这条我知道，别烦我"。同一个位置不会再提示，**除非那一行内容变了，或者相关变量的类型变了**。

### 2. 灯泡

有些修复天生跨行——比如初值要加到声明上、`#include` 要插在文件顶部、缺的 `}` 在文件末尾。灰字只能改单行，这些走灯泡：

```
💡 初始化为 0               int sum;  →  int sum = 0;
💡 初始化为 NULL            指针类型
💡 补上缺失的 '}'           未闭合的花括号
💡 插入 #include <stdio.h>   用了 scanf 却没 include
💡 补成 'T--'               while (T-) 少写一个减号
💡 删除多余的数值            误粘贴进来的数字
💡 补上缺失的格式符 '%c'      printf("%d", c, ch) 少写一个 %c
💡 删除多余的实参            或者多传了一个
```

灯泡里有多个方案时（比如"补格式符"还是"删实参"），会并列列出，由你决定。

### 3. 诊断（Problems 面板）

修不了的、或修法取决于意图的问题，进 Problems 面板并在行内标注：

```
未声明的标识符 'i'
格式符 '%d' 与 'r' 不匹配，应改为 '%lld'
代码中有非 ASCII 字符 '，'，应改为 ','
未声明的标识符 'i'          ⚠ 未声明的标识符 'i'
```

默认中文。想切英文：设置里搜 `cfix.locale`，改成 `en`。

### 4. 补全

输入 `stdio.h` / `string.h` 函数名的前两个以上字符：

```c
pr     ⏎ Tab →  printf("%d\n", );
                    ↑ 光标停在这里，再按 Tab 跳到下一个占位符
```

支持 24 个常用函数（`printf`、`scanf`、`strlen`、`strcpy`、`strcmp`…）。

### 覆盖哪些问题

53 条规则，默认开启 31 条。分六类：

- **格式化输入输出**：`scanf` 缺 `&`、格式符与实参类型不符、参数个数不对、`%s` 无宽度、`sprintf` 越界
- **字符串**：`char*` 用 `>` 比较（比的是地址不是内容）、`s[0] == "P"`（字符比指针）、缺 `#include`
- **类型与函数**：未知类型名拼错、隐式声明、参数数组退化、有符号/无符号比较
- **通用语法**：条件里误用 `=`、缺分号、表达式残缺、括号不配对、漏写 `#`、误粘贴残留
- **安全与栈**：局部变量超限、变长数组栈溢出风险、除零
- **中文输入法**：全角标点、全角字母数字（如 `ｉｎｔ`、`１２３`）

## 二、安装

### A. 基于 Open VSX 的编辑器（VSCodium / Gitpod / Code OSS / Trae 等）

扩展面板搜 `zr-c-fix`，或命令行：

```bash
ext install zr2863356099-sudo.zr-c-fix
```

### B. 微软官方 VS Code

> ⚠️ **微软的扩展面板只查微软自己的市场，搜不到本插件。**

从 [Releases](../../releases) 下载 `zr-c-fix.vsix`，然后任选其一：

**命令行**

```powershell
code --install-extension zr-c-fix.vsix
```

**界面**

1. 打开扩展面板（`Ctrl+Shift+X`）
2. 点面板右上角的 `...`
3. 选 **从 VSIX 安装…**
4. 选中 `zr-c-fix.vsix`
5. 装完按 `Ctrl+Shift+P` → `Reload Window`

### C. 从源码构建

```bash
git clone https://github.com/zr2863356099-sudo/zr-c-fix.git
cd zr-c-fix
pnpm install
pnpm build        # 产出 dist/extension.js + 两个 wasm
pnpm package      # 产出 zr-c-fix-<version>.vsix
```

## 三、日常使用

1. 打开一个 **语言模式为 C** 的文件（右下角显示 `C`；显示 `Plain Text` 就点它改成 C）
2. 正常写代码
3. 光标停在哪一行，0.3 秒后那一行有问题就会提示
4. 灰字按 `Tab` 接受、`Esc` 忽略；跨行的修复按 `Ctrl+.` 挑灯泡

### 命令面板（`Ctrl+Shift+P`）

| 命令 | 用途 |
|---|---|
| `cfix: 接受修正` | 等同 Tab |
| `cfix: 忽略修正` | 等同 Esc |
| `cfix: 检查整个文件` | **无视一切过滤**，列出全部问题（排查用） |
| `cfix: 补上缺失的 }` | 未闭合花括号一键修复 |
| `cfix: 导出分析结果` | 把当前文件的分析写成 JSON，排查用 |

### 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `cfix.enable` | `true` | 总开关 |
| `cfix.preset` | `core` | 规则集 `core`(31) / `standard`(50) / `all`(53) |
| `cfix.locale` | `zh` | 诊断语言 `zh` / `en` |
| `cfix.completion.enable` | `true` | 函数模板补全 |
| `cfix.correction.enable` | `true` | 灰字纠错与诊断 |
| `cfix.correction.debounceMs` | `300` | 停手多久后检查（毫秒） |
| `cfix.stackLimitKB` | `1024` | 普通函数栈帧阈值，递归函数固定 64 KB |
| `cfix.rules` | `{}` | 逐条开关，如 `{"shadowing": "off"}` |

## 四、常见问题

### Q1：光标停在有问题的行上，但没有灰色小字

按可能性从高到低排查：

**① 这个问题本身没有"能自动修"的方案**

不是所有问题都能修。下面这几类**只提示不修**，因为它们取决于你的意图：

| 问题 | 为什么不修 |
|---|---|
| 未声明的变量（附近没有相近的变量名） | 不知道该声明成什么类型、放在哪 |
| 除零 | 加检查还是加提前返回，取决于逻辑 |
| 变量遮蔽外层同名变量 | 改名涉及整个作用域 |
| `gets()` 参数缺失 | 不知道该传哪个缓冲区 |

这类问题会显示为**行内灰色注解**（带 ⚠），不会显示可 Tab 的修改。

**② 光标不在那一行**

灰字只看**光标所在行**。把光标点到有问题的那行，停 0.3 秒。

以前需要"敲一下空格"才触发，从 0.2.x 起光标移动就会触发，不需要再敲。

**③ 文件有语法错误，且问题就在出错的那几行**

文件语法错误时，出错行上的语义类提示会被抑制（避免连锁误报）。但**其它干净的行照常提示**。

验证方法：跑一次 `cfix: 检查整个文件`，它能无视过滤列出全部问题。

**④ 扩展没生效**

- 右下角状态栏有没有 `cfix` 字样？没有 → 文件语言模式可能不是 C
- 刚装完没重启 → `Ctrl+Shift+P` → `Reload Window`
- 版本太旧 → 扩展面板看版本号，对比 Releases

### Q2：按 Tab 没反应，或者 Tab 变成了缩进

**最常见的原因是和 AI 补全扩展抢键。**

`Tab` 在 VS Code 里是「接受建议」的公共键，多个扩展都想用：

| 扩展 | 默认用 Tab 做什么 |
|---|---|
| GitHub Copilot | 接受 AI 补全 |
| 通义灵码 / 豆包 / Codeium / TabNine / Continue | 同上 |
| Vim / Neovim 插件 | 接管 Tab，当普通按键处理 |
| 本插件 | 接受灰色修正（仅当 `cfix.suggestionVisible` 为真） |

两边都「可见」时，谁拿到 Tab 取决于键位绑定的匹配顺序，结果不稳定。表现就是：灰字出现了，按 Tab 却变成了 AI 的补全，或者毫无反应。

**怎么确认是冲突**：灰字出现时按 `Tab`，如果代码变成了**别的**内容（不是灰字显示的那个），就是被抢了键。临时禁用可疑扩展再试一次即可确认。

#### 解决办法（任选其一）

**方案 A —— 给本插件换个键（推荐）**

命令面板 → `Preferences: Open Keyboard Shortcuts (JSON)`，在 `keybindings.json` 里加：

```json
{
  "key": "ctrl+enter",
  "command": "cfix.acceptCorrection",
  "when": "editorFocus && cfix.suggestionVisible"
}
```

Tab 留给 AI，灰字出现时用 `Ctrl+Enter` 接受。

**方案 B —— 让 AI 换键，Tab 留给本插件**

```json
{
  "key": "alt+]",
  "command": "editor.action.inlineSuggest.commit",
  "when": "inlineSuggestionVisible"
}
```

**方案 C —— 在 .c 文件里关掉 AI 补全**

```json
{
  "github.copilot.enable": {
    "*": true,
    "c": false
  }
}
```

**方案 D —— 用命令面板（永远不受键位影响）**

`Ctrl+Shift+P` → `cfix: 接受修正`

**方案 E —— 使用 Vim 插件时**

Vim 插件在插入模式下会接管 Tab，建议用方案 A，或者只在普通模式下用命令面板。

> 本插件不会关闭你的 AI 补全，两者可以共存，只是 Tab 的归属需要你选一个。

### Q3：和 C/C++ 扩展（`ms-vscode.cpptools`）冲突吗

**不冲突，但会看到两套标记。**

| | C/C++ 扩展 | 本插件 |
|---|---|---|
| 依据 | 调用真实编译器 / IntelliSense | 内置语法分析 |
| 标记 | 红色波浪线 | 蓝色/黄色波浪线 + 灰色小字 |
| 能否修 | 只报 | 能 Tab 一键修 |

两者各画各的，互不干扰。如果你觉得红色波浪线太吵，可以在设置里关掉 C/C++ 扩展的实时错误提示：

```json
" C_Cpp.errorSquiggles": "disabled"
```

（注意去掉开头的空格，写 `"C_Cpp.errorSquiggles"`）

**为什么同一个问题它报我不报？** 见 Q4。

### Q4：C/C++ 扩展报错了，但本插件不给修复

几种可能：

- **问题类型不在覆盖范围内**（比如数组越界、空指针解引用，这些只有运行时才能发现）
- **只覆盖 `stdio.h` 和 `string.h`**：用了 `<math.h>`、`<ctype.h>`、`<stdlib.h>` 时，规则对不认识的函数一律沉默
- **推断不出来就不报**：类型未知、长度未知时宁可不提示，避免猜错
- **文件语法错误且问题在出错行上**（见 Q1 ③）

### Q5：中文标点、全角字母能不能自动改

能。`，`、`；`、`（）`、`ｉｎｔ`、`１２３`、`＃include`、弯引号 `""` 都会转成半角。

某些字符无法映射（比如句号 `。`、顿号 `、`），只提示不自动改——因为不知道该换成什么。

**修完全角字符后，一些"未闭合花括号"的假警告会自动消失**，因为那些错误本来就是全角字符带出来的。

### Q6：打开文件就满屏"未声明的标识符"，但代码是对的

这种情况在旧版本（0.1.x）会出现，原因是函数表当时只覆盖 `stdio.h` / `string.h`，用 `sqrt`、`isdigit`、`malloc` 会被误判"未声明"。

**0.2.x 已修复**：文件 include 了其它头文件时，规则对不认识的函数一律沉默。如果仍然出现，先确认版本。

### Q7：写 `int new = 5;` 被说成"C++ 语法"

这是旧版本的误报（`new`、`cout`、`cin` 在 C 里是合法标识符）。相关规则已在 0.2.9 移除。

### Q8：粘贴进大段数字（比如测试数据）后全是波浪线

那是"误粘贴残留"。跨行的残留用灯泡 `💡 删除多余的数值` 一次清掉。

### Q9：磁盘上的文件和编辑器里的不一致

本插件分析的是**编辑器里的内容**，不是磁盘文件。改完没保存也能正常提示。

如果排查问题时需要把实际内容发出来，跑 `cfix: 导出分析结果`，会生成 `%TEMP%\cfix-analysis.json`，里面包含编辑器里的**真实文本**和分析结果。

### Q10：性能

- 分析有 300ms 防抖，连续打字不会反复触发
- 单个学生作业文件（几百行）分析在毫秒级
- 如果确实卡，可以调大 `cfix.correction.debounceMs`（比如 600）

### Q11：它会不会联网 / 上传我的代码

**不会。** 扩展运行时不发起任何网络请求，不调用编译器，不读系统头文件，没有遥测。C 语法解析用的是打包在扩展里的 WASM 文法。装完断网照常工作。

仓库里的 `scripts/net-guard.js` 就是验证这一点的工具：在扩展宿主进程内挂钩所有网络出口，跑完整测试后记录为 0 条。

### Q12：为什么某些错误它永远不报

- **输出格式错误（PE）**：该用空格还是换行取决于题面，静态分析无从判断
- **运行时问题**：数组越界、空指针解引用、整数溢出
- **其它头文件的函数**：见 Q4
- **宏展开后的错误**：只分析源码文本，不展开宏（除了简单的 `#define` 常量）

## 六、反馈

遇到本文档没覆盖的问题，请带上这几样信息提 issue：

1. 版本号（扩展面板里能看到）
2. 出问题的那几行代码
3. `cfix: 检查整个文件` 的结果截图
4. Output 面板 → 频道选 `cfix` → 最后几行日志

有这四样，基本能定位。
